# Contributing to Harnett Mesh

[Home](README.md) | [Documentation Index](docs/README.md)

Harnett Mesh is being built as a practical, community-oriented project. Clear
documentation and careful testing are as valuable as technical implementation.

## Suggesting documentation changes

Open an issue describing what is unclear, missing, or outdated. Include the
intended audience and a proposed correction when possible. Small corrections can
be submitted directly as pull requests.

## Issues

Use issues for questions, documentation gaps, proposed standards, field-test
feedback, and reproducible problems. Do not include private site information,
exact infrastructure locations, credentials, keys, or other sensitive details.

## Pull requests

Use pull requests for focused changes that are easy to review. Explain what
changed and why. Link related issues when applicable. Changes to public standards
should identify whether they are proposed, tested, or approved.

Technical claims should be supported by reliable references, reproducible tests,
or field observations. Avoid presenting estimates or assumptions as established
network behavior.

## Public-repository safety

This repository is public. Never submit:

- Exact repeater coordinates or private infrastructure locations
- Infrastructure access instructions or sensitive AuxComm operational information
- Passwords, API keys, administration keys, channel keys, or other credentials
- Private configuration or information that could identify protected sites

Review changes carefully before submitting them. If sensitive information is
shared accidentally, report it to the maintainers immediately rather than
continuing to distribute it.
